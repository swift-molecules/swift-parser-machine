# swift-parser-machine

Use this package when a grammar's nesting depth is set by the input (balanced brackets, nested elements) and parsing must not overflow the native call stack, or when a document is re-parsed after small edits and the part before the edit should be served from a cache. Describe the grammar with `Machine.Parser.build` or, for a self-referential grammar, `Machine.Parser.recursive`, composing `Machine.Parser.Expression<Input, Failure, Output>` values in a `Machine.Parser.Builder<Input, Failure>`; the result is a `Machine.Parser.Parser<Input, Output, Failure>`, and its `parse.incremental` gives a memoizing `Machine.Parser.Parser.Parse.Incremental`. To run an existing `Parsing` value from swift-parser through the machine unchanged, use `Machine.Parser.Compiled<P>` (compiles on first use) or `Machine.Parser.Prepared<P>` (compiles at initialisation). When the grammar's depth is bounded and no reuse across edits is needed, conform to swift-parser's `Parsing` directly instead.

## Laws

- Execution is iterative. Every combinator, and every entry through `Machine.Parser.Reference.expression(in:)`, pushes a frame onto a heap stack; no combinator recurses natively. Only the code inside a leaf runs on the native stack, so a `Machine.Parser.Compiled<P>` or `Machine.Parser.Prepared<P>` built with the `.leaf` witness turns the whole source parser into one leaf and gains no stack safety for its internals.
- `Machine.Parser.oneOf` is ordered, committed choice. Alternatives are tried left to right, each starting from the input position at which the choice began. The first success wins and is final: a later failure in an enclosing sequence never returns to try the remaining alternatives. When every alternative fails, the last alternative's failure propagates. An empty list of alternatives traps when reached.
- A failure rewinds the input only to the position saved by the nearest enclosing `Machine.Parser.oneOf`, `Machine.Parser.many` or `Machine.Parser.optional`. `Machine.Parser.sequence` saves no position: when its second part fails with no enclosing recovery point, the input stays where the failing leaf left it.
- `Machine.Parser.many` never fails. It stops at the first failing iteration and rewinds to the end of the last successful one. It also stops after an iteration that succeeded without consuming input, and that iteration's value is included in the result.
- `Machine.Parser.optional` never fails. When its child fails it rewinds to where it started and yields `nil`.
- A failure thrown by a `Machine.Parser.Expression.tryMap` transform is recovered exactly like a leaf failure.
- `maxDepth` counts nested entries through the self-reference; `Machine.Parser.build` sets no limit. Reaching the limit is a failure that an enclosing `oneOf`, `many` or `optional` can recover from. If nothing recovers it, `onDepthExceeded(limit)` is thrown; when no `onDepthExceeded` was given, the process traps, unless `Failure` is `any Error`, which receives the package's internal depth error. `Machine.Parser.Compiled<P>` and `Machine.Parser.Prepared<P>` set no limit.
- `Machine.Parser.Compiled<P>` compiles its source at most once, on the first `parse` or `prepared()`. All copies share the same program.
- `Machine.Parser.Parser.Parse.Incremental` memoizes every node visit, keyed by input checkpoint and node. A success records the output and end checkpoint; a hit seeks the input to that end checkpoint and replays the output without running the leaves or the `map`, `combine` and `flatMap` closures beneath it. A failure is recorded only when it has the grammar's `Failure` type, so depth-limit failures are never cached, and a hit replays it through the same recovery as a fresh failure.
- The memo table persists across calls on the same `Machine.Parser.Parser.Parse.Incremental` value and has no eviction. It does not see the input's contents: after the input changes, the caller must call `invalidate` before parsing again, or stale results are returned. `clear()` empties it; the `capacity` initialiser only reserves space.
- `invalidate(_:)` and `invalidate(from:)` keep a success only if it ended at or before the edit's `start`, and a failure only if it began before `start`. Nothing after `start` is shifted by the edit's length; `oldEnd` and `newEnd` are not consulted.
